## Что проверяют тесты

- Реальный PostgreSQL: регистрация, одобрение, создание и уникальная нумерация.
- Полный цикл принятия, работы, вопроса, ответа, завершения, переоткрытия, повторного завершения, подтверждения и рейтинга.
- Два независимых DB-сеанса и два потока одновременно принимают одну заявку: ровно один успешный результат, второй — 409.
- Повторный ключ создания не создает вторую заявку.
- Отмена новой заявки и запрос отмены после начала работ.
- RBAC/IDOR: чужая заявка недоступна сотруднику; внутренние заметки не выдаются; каталоги пользователей, аналитика, аудит и настройки защищены.
- Cookie-аутентификация, CSRF, ограничение входа и запрет записи произвольного статуса.
- SLA, изменение приоритета, автозакрытие, недублирующиеся SLA-пороги.
- Фильтры, CSV/XLSX и аналитика по записям БД.
- Подключение получателя по одноразовому токену, отсутствие доставки по одному username, статусы доступности, смена категорий без перезапуска, три режима маршрутизации и резервный руководитель.
- Тестовый транспорт: автоматическая доставка числовым chat ID, сохранение ошибок, блокировка одного получателя без потери остальных доставок, 4 попытки с backoff, обновление прежних сообщений, отзыв доступа перед отправкой.
- Реальные обработчики aiogram через `Dispatcher.feed_update`: FSM регистрации/заявки, подтверждение перед записью, «Назад», «Отмена», сохранение FSM в БД, дедупликация update ID и устаревшая кнопка принятия. Сеть заменена FakeSession.

## Браузерный сценарий

Вход администратором → открытие всех административных разделов → создание заявки с предварительным просмотром → принятие → начало работ → запрос информации → ответ → продолжение → завершение → подтверждение → 5 звезд → поиск заявки по номеру.

Проверены отсутствие исключений браузера и горизонтального переполнения всей страницы при ширине 390 px. Широкие таблицы прокручиваются внутри своих контейнеров. Проверки оставили дополнительные тестовые заявки в демобазе.

## Исправленные проблемы окружения

- npm cache и Buildx пытались писать в read-only home: кэши перенесены в `/tmp`.
- Docker images не наследовали доверенный CA облачного egress-прокси: добавлен BuildKit secret и read-only runtime mount. TLS-проверка не отключалась.
- BusyBox wget направлял внутренний healthcheck через прокси: для обращения к `127.0.0.1` используется `-Y off`.

## Оставшиеся проверки и предупреждения

В текущем экземпляре настоящий токен задан через локальный `.env` и проверен с Telegram API. Получатель предварительно одобрен по числовому ID; привязка приватного chat ID происходит после его личного `/start`. Пока этот шаг не выполнен, реальная персональная доставка не заявляется как проверенная. При переносе ZIP/Git на другой компьютер задайте собственные локальные секреты и выполните `docs/demo.md`. Результаты FakeSession не выдаются за внешнюю доставку.

Vite предупреждает о bundle больше 500 kB; сборка успешна. Перед production рекомендуется разделить загрузку графиков и страниц. Тестовая зависимость Starlette сообщает предупреждение о deprecated AnyIO alias; тесты проходят. Эти предупреждения не скрыты и не считаются ошибками проверки.

Конфигурационные поля облачной среды `install_script` и `start_skill` сохранены в черновик. Сохранение не публикует среду. Для последующих задач нужно просмотреть/сохранить настройки и опубликовать среду через интерфейс.

## Проверки после подключения токена

Добавлены тесты предварительного одобрения получателя: посторонний ID не может подключить учетную запись, отключенный или ожидающий одобрения получатель не активируется через Start. Существующий webhook сохраняется до явного разрешения миграции. Telegram HTTP transport использует системный HTTPS proxy и доверенную CA-цепочку, сохраняя `CERT_REQUIRED` и проверку имени хоста. Всего 40 успешных тестов.

При восстановлении облачного экземпляра PostgreSQL был остановлен. После запуска Compose повторный прогон прошел; это было состояние окружения, а не ошибка приложения.
